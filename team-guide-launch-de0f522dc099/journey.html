Git & ClickUp

Your change travels in two hops — and you only drive the first.

ClickUp holds the work: every ticket, status, and comment. Git holds the code: every change, traceable back to its ticket. Your change rides your own small PR into the feature branch. One integrator then takes the whole feature to staging. You never touch a shared branch. The agent drives it all for you; your job is to recognise what it’s doing and approve.

You never type git commands yourself. Your whole invocation is /ticket-to-ship FRC-813 — the skill plus your ticket ID; every git rule on this page happens for you. When something touches the shared repo (a push, a PR) the agent asks first. Read that confirmation before saying yes — that’s your control point.

The one thing you type /ticket-to-ship <ticket-ID> e.g. /ticket-to-ship FRC-813 /ticket-to-ship <ticket-ID> --lean one-shot, for changes you judge simple

Worried you’ll break someone else’s work? You can’t.

Three protections are built into the setup:

1. Your branch is yours aloneEvery change gets its own branch, named after its ticket. Nobody else works on it.
2. Shared code only changes by reviewed PRNothing lands until another person reviews your change and merges it.
3. The risky move is never yoursOne integrator replays the feature onto staging. Anything unclear gets parked as a draft PR for an engineer.

Step 4 · The feature owner

Review, then squash-merge

The feature owner reviews your PR and squash-merges it. “Squash” means your work lands as one clean commit in the feature branch. Your branch is now done; the next change starts a fresh one. The feature branch collects everyone’s merged changes, and it only changes through reviewed PRs like yours.

The feature branch — named after the feature’s ticket feat/<REF>-<kebab> e.g. feat/FRC-813-referral-rewards
Step 5 · The integrator

One move takes the whole feature to staging

The integrator is the engineer who owns the feature branch — the same person who reviewed your PR. They replay the finished feature onto the latest staging, then open one PR for the whole feature. Tony reviews it. It merges with a merge commit, never squash, so every commit keeps its ticket ID.

The detour · only if a safety check trips

The PR parks itself and an engineer takes over

Sometimes staging moved and the merge isn’t clean. A safety check catches that before anything merges. The PR waits as a draft, gets the needs-engineer-integration label, and an engineer resolves it on GitHub. This is the system working. If no check trips, this step is skipped entirely.

Step 6 · Gated promotion

Merged to staging, then promoted rung by rung

The feature merges into staging and the ticket flips to staging. From there the whole feature is promoted staging → uat2 → master, with a release check at every rung. Nothing skips a rung, and a fix re-enters through the same feature branch.

One status ladder, mostly agent-flipped

The ticket is the single source of truth for where work stands. Most flips are the agent’s job — done only when a stage’s gate is green, never on hope. At every green gate it also posts a handoff comment (what was done, what’s next) — the baton the next session picks up. If a gate fails, the status does not move. Get set up

Seen the journey? Get it on your laptop

One five-minute update and everything above works on your machine. Most of the team already has the workspace — if that’s you, take the left path. Brand-new machine? Take the right.

Already have it on your laptop?

Most of the team — three steps, about five minutes.

  1. Open the ai-setup folder in a terminal

    A terminal is the text window where you type commands. You need it pointed inside the ai-setup folder.

    How to open a terminal in this folder

    Mac: in Finder, right-click the ai-setup folder → Services → New Terminal at Folder. (Or open Terminal and drag the folder onto its window.)
    Windows: open the ai-setup folder in File Explorer, click the address bar, type powershell, and press Enter.

  2. Catch up once with git pull

    Run this exactly once. The update-checker ships inside this very update, so this manual pull is the one time you fetch it by hand. After today, your session checks for updates at startup and asks before applying — nothing changes until you say yes.

    Mac, Linux & Windows git pull

  3. Run the updater

    This brings your laptop in line with the new standard. It looks before it touches: it scans everything, prints a plain-language report of what it found, and asks you once before changing anything.

    Mac & Linux bash bin/update.sh
    Windows (PowerShell) powershell -ExecutionPolicy Bypass -File bin\update.ps1

    Just want to preview? Add --scan-only (-ScanOnly on Windows) to see the report and change nothing. Already hand-fixed your database? Add --skip-docker (-SkipDocker).

    If it says SKIPPED anywhere, copy the whole output and paste it into the ClickUp rollout channel. A SKIPPED item means the updater safely left something alone (e.g. your uncommitted work) — nothing is broken, but we want to help you finish.

When something breaks

You’re not stuck — try these, in order

Most snags fix themselves in one message. Work down this list.

Where do errors show up?

When something crashes while you’re running the app on your laptop, the error appears right in the terminal window where you started it — that’s the first place to look. A copy is also saved to a dated log file (ApplicationLogs/<date>.log) inside the pitchinAPI folder.

Ask in the session

Paste the exact error into your Claude Code session and ask it to fix it. It can read your files and usually sorts it out.

Run fix-workspace

If the workspace itself feels off — docs or skills missing, an update said it skipped — type “run fix-workspace” in a session in your ai-setup folder. It backs up anything you changed, then resets your copy to the clean published version. It never touches the product code repos.

Share the update report

If the updater said SKIPPED, paste its whole output into the ClickUp rollout channel. That output tells us exactly what to help with.

Ask a human

Still stuck? Post in the ClickUp rollout channel. Nicholas maintains the workspace — describe what you did and what you saw.
