Words

Five words this page uses

  • Requirement — one thing pitchIN can ask for, defined once in the library (name, optional generic help text, a kind, its settings). A note for one issuer goes on the checklist item, not here (RequirementItem).
  • Template — an ordered list of requirements, published as versions. Each application type (Note, Equity, Token) has an at-submission template (snapshot at submit, carrying the fee) and an at-approval one (merged in when an admin or superadmin presses Start deeper checks and picks it); Undecided has at-submission only. Several per role, one default. Seven seeded by name, empty library. The submitted application form is never in a template: the snapshot always puts it first.
  • Checklist item — one requirement on one issuer's checklist, copied from the library at snapshot — or, added later (P2P-74), from the library or typed as a one-off, optionally saved there too. Only the at-approval merge or a reason-logged change can alter it after.
  • Kind — decides what the issuer does and admin sees. Tickets/admin screens call it type (mapping in the kinds table); the issuer sees only the item's own name.
  • Status — Not started, In progress, With pitchIN, Returned, Accepted, Out of date; the sentence per (kind × status) is a fixed platform string, never admin-written. Grouped by whose turn it is — Yours to do, With pitchIN, Done — never ranked. A seventh, Past due, is reserved and never shown.

Words that are easy to mix up
  • Four different approvals. Application approval — Start deeper checks (Lane B, P2P-130, on the onboarding tab): we want to go further with this business; admin picks the at-approval template and it merges in. Credit (P2P-32) later decides whether we host the deal. Decline onboarding (P2P-130) closes the application at any point, with a reason the issuer reads. Terms approval — admin approves the offer terms item (P2P-87). Onboarding approval, also called sign-off — one admin closes the application when every required item is accepted or waived (P2P-73). Accepting one item — every review. None of them makes a funding round visible to investors.
  • Acknowledgement is a kind of item; acknowledged is a kind of record. The item is what the issuer reads and ticks; the record is the row one confirmation writes.
  • Funding round (what the issuer reads) = Campaign (code) = listing (what investors see). The note is the instrument, created at close (P2P-26).
  • Return / Returned is the one word for admin needing something different. Attest / Withdraw is the pair for an admin-verified item. Waive records that an item is not needed; it is also the only way to undo an acceptance.

Accept and Return only appear once something has actually been submitted — the submitted-payload rule, evaluated from what was actually sent (files, form rounds, records), never from the status: a file has at least one file version, a form at least one sent round, an acknowledgement a record, a fee a proof (Accept only). The type is a chip on every admin-list row (File request · Form · Payment · Acknowledgement · Admin-verified · Offer terms), filterable by type and status, with one line saying what that type lets admin do. Any admin can action any item — there is no team ownership and no assignment.

Equity block P2P-88, to be finalised

Reshapes today's ECF Offer creation step onto this kind; its fields are undecided — P2P-88, "[To be finalised]". Until it ships, an equity application has no offer-terms item at all — not disabled, not a placeholder — and keeps today's Offer step outside the portal (P2P-124).

Token phase 2

Token applications use this portal with no offer-terms item; after sign-off pitchIN agrees the deal off-platform. Token terms are a phase-2 placeholder (P2P-136): same pattern, a CampaignTokenTerm block.

Edge cases: phase-2 drafts, waiving, missing cells

Agreement and Task rows are drafts owned by P2P-75 / P2P-79, not exported with the phase-1 keys above: Agreement — We will release this for signing once your documents are accepted. · Ready to sign. · Signed. We will countersign and keep the executed copy. · We need this signed again. · Signed by both sides. · The agreement has changed. Task — Complete this on your {target} page. · Some of it is still to fill in. · Sent, reviewing. · We need some of it changed. · Accepted. · We need your {target} page updated.

A waived item shows as Accepted with one different sentence: "Accepted. We did not need this from you." — admin's reason is never shown to the issuer, and no due date is shown anywhere.

A cell marked "never" is unreachable for that kind — the API's reachability map and the string-table test (story 31.3) enforce this. Slots: {amount} is the snapshotted fee amount, money-formatted; {target} is the page name on a task item — no company name or amount is ever a string literal.

Two more fixed sentences: after sign-off, "Onboarding complete. We have everything we need."; if Help fails to send, "We could not send your message. Try again, or email {support email}." Equity and token: see offer terms.
