Shared tables

Two existing tables change

Campaign

existing · changedthe three new columns are right; two renames, one index, and the backfill rule change
  • rename
    ProductType → AssetClass · ShariahType · MinimumInvestmentAmount — built as specified, with one rename: the column and its enum are AssetClass (Equity 1 · Note 2 · Token 3), named for what the investor ends up holding rather than for the licensing regime. The forms module keeps its own ProductType (ECF · TCF · P2P) untouched. Database default must be a real value, not 0.
  • rename
    PricePerShare → PricePerAsset — the note's unit price lives here, shared with equity. How the rename is done (model now, column later, or both) is Tony's call since equity code reads it.
  • add
    unique index on Slug — Campaign already has a Slug column and an index on it, but that index does not enforce uniqueness. All campaigns will share /invest/:slug, so it must. Check existing rows for duplicates first.
  • retype
    backfill — every existing campaign is equity, so AssetClass = Equity for all; ShariahType = Islamic where the share class is an Islamic class or the payment account is DuitNow Shariah, otherwise Conventional. Written so a re-run cannot undo a corrected row.

Investment

existing · changedone new column; four columns get instrument-agnostic names, one falls out of use for notes
  • rename
    ShareQuantity → AssetQuantity — for a note: amount ÷ the campaign's price per asset, stored at investment.
  • rename
    PricePerShare → PricePerAsset — copied from the campaign at investment.
  • rename
    ShareType → AssetType — Note for a note investment.
  • rename
    EcfAccountNo → AccountNumber
  • add
    NoteRegisterId FK, nullable — set at close, pointing at the holder's register row; equity's ShareId. Two investments by one holder point at the same row. A refunded investment never gets one.
  • keep
    IsNominee — always true for a note. LotQuantity — unused by notes. The investment set-up is being changed separately to remove lots (separate ticket); what happens to this column belongs there, and the renames above hold either way. Everything else unchanged.
Note tables

One is right, one is new, three change shape

CampaignNoteTerm

built · adjustthe debt terms are right; the fee block needs three columns in and four out
  • keep
    CampaignId (unique) · NoteReference · ProductClass · InterestRate · TenureValue · TenureUnit · RepaymentFrequency · Purpose · RiskGrade · RiskRationale · DefaultClass · FaceValue · AdvanceRate · CounterpartyName · CounterpartySector
  • keep
    SuccessFeeRate · EarlySettlementFeeRate · LateFlatFee · LateInterestRatePerDay — all nullable until the setup screen stamps them from P2P-27.
  • add
    GracePeriodDays · DelinquencyDpd · DefaultDpdThreshold (int, nullable) — the servicing terms the issuer agreed and the note discloses (Annex A §5): how many days of grace before a late fee, when the note counts as delinquent, when it counts as in default. They are copied onto the note at setup so a later change to the platform setting cannot reach a note already issued.
  • remove
    LateFeeCap · CorrespondenceFee · GSTRate · RenewalFee — correspondence fee and tax are live platform values, never copied onto a note; the cap was never specified; the RM150 annual AR/AP facility renewal (§6.1) is invoiced when it happens, like the restructuring fee, and is not a term of one note.
  • keep
    audit columns — CreatedBy, CreatedAt, ModifiedBy, ModifiedAt: who created or last changed the row, and when. Every table on the platform has them. This table carries no status and no unit price; it is the offer as disclosed, frozen after setup. It is what the listing showed. Once the note is issued nothing reads it again: servicing reads Note.

Note

new tablethe issued loan, created at close; equity's counter
  • add
    Id · CampaignId (unique, 1 : 1) · NoteReference (copied from the terms)
  • add
    PrincipalIssued decimal(15,2) · Units int — the amount raised and its units at close.
  • add
    InterestRate · TenureValue · TenureUnit · RepaymentFrequency · DefaultClass — the loan's terms in force. Copied from the offer at close; changed only by a restructure, together with a new schedule version. The offer on CampaignNoteTerm never changes, so what was disclosed and what is now in force are both on record.
  • add
    GracePeriodDays · DelinquencyDpd · DefaultDpdThreshold · EarlySettlementFeeRate · LateFlatFee · LateInterestRatePerDay — the servicing terms, copied from the offer at close for the same reason. The rule: CampaignNoteTerm is what the listing showed; Note is what servicing reads; anything both need is copied once, at close. Success fee stays on the offer (charged once at disbursement); management fee, tax and correspondence fee are live platform values and sit on neither.
  • add
    Status enum NoteStatus — Issued 1 · Performing 2 · Late 3 · Restructured 4 · DefaultInRecovery 5 · DefaultLowNoRecovery 6 · WrittenOff 7 · ClosedRedeemed 8. No FailedRefunded: the Note row is only created once Admin confirms success, so a failed raise never has one; the refunds are on the Investment rows.
  • add
    IssuedAt · DisbursedAt · MaturityDate (date) · ClosedAt — when the note was issued, when the money went to the issuer, when the last instalment falls due, and the date the note reached Closed or Written off. All nullable except IssuedAt.
  • add
    PrincipalRepaid · InterestPaid · PrincipalOutstanding decimal(15,2) · LastPaidAt nullable — running totals, written only by payouts.
  • add
    audit columns — who created or last changed the row, and when. No soft delete.

NoteRegister

built · reshapethe holding record, one row per holder as equity's Share is; loses the copies of terms, the servicing state and the fee columns, gains the parent, the holder identity and the running share
  • add
    NoteId FK — the parent. CampaignId stays as a convenience copy, as Share keeps one.
  • remove
    InvestmentId — the link runs the other way, as equity's Investment.ShareId does: each paid investment points at its holder's row (Investment.NoteRegisterId, above). One row per holder per note, unique on (NoteId, UserId), built at close by adding up that holder's paid investments, exactly as Share consolidates. A holder who invested twice has one row; a refunded investment has none; a row nothing points at is a secondary holding, for later.
  • keep
    UserId · SliceReference — unique across the platform, one per holder. · PrincipalAmount — the holder's total.
  • add
    CompanyId — copied from the campaign, as Share does; the track-record query path. · Units int
  • remove
    InvestorCategory — the investor's category at the time of investing is already recorded on the Investment rows that point at this one, and the investor's current details live on the user record. Nothing to copy here.
  • replace
    Status (ten note states) → HoldingStatus — Active 1 · Exited 2 · WrittenOff 3. Generic on purpose: a holder is still holding, has left (repaid in full, bought back or transferred), or was written off with the note. No Refunded: register rows are only created at close, so a failed raise never reaches this table. Plus ExitedAt and ExitAmount, nullable; the event that wrote them says why.
  • remove
    InterestRate · TenureValue · TenureUnit · ExpectedInterest · TotalPayable · DefaultClass — facts about the loan; read them from the terms.
  • remove
    DaysPastDue — computed by servicing, never stored. · FundedAt · DisbursedAt · MaturityDate · ClosedAt — dates of the loan, on Note.
  • keep
    PrincipalRepaid · InterestRepaid — rename the second to InterestReceived if you like; both are the holder's running share.
  • add
    PrincipalOutstanding decimal(15,2) · LastPaidAt nullable — the rest of the running share, written only by payouts. No fee or net columns: the fee taken and the net credited are facts of each payout, not of the holding, and live on the F4.3 allocation, as PSTX keeps trade fees on the contract rather than on the holder.
  • add
    DocumentAttachmentId → attachment store, nullable, as Share's certificate id · ExecutedAt nullable — set at close by the minting operation. No ConsentId here: consent is given per payment and stays with the Investment (lane D).
  • remove
    IsDeleted · DeletedAt — rows are never deleted; foreign keys restrict, not cascade.

RepaymentSchedule

built · re-parentright columns, wrong parent
  • replace
    NoteRegisterId → CampaignId — one set of versions per note, never per investor. The campaign is the parent rather than the Note row because the Indicative version exists at setup, before the note is issued; the campaign and the note are 1 : 1, so nothing is lost. Unique on (CampaignId, VersionNo).
  • add
    filtered unique index on CampaignId where IsCurrent — exactly one current version per note, enforced by the database.
  • add
    InterestRate · TenureValue — the terms this version was built on, so a restructure that changes them is provable version by version.
  • keep
    VersionNo · ScheduleType · IsCurrent · TotalPrincipal · TotalInterest · TotalPayable · GeneratedAt · audit
  • remove
    IsDeleted · DeletedAt — versions are never deleted.

RepaymentScheduleRow

built · trimone row per instalment: when it is due and how much principal and interest it carries. This is the Annex A §4 table investors are shown, exactly
  • keep
    RepaymentScheduleId · InstalmentNo · Principal · Interest · Total — the ticket names them PrincipalAmount, InterestAmount, TotalAmount; either name, but the ticket and the code must agree.
  • retype
    DueDate → date — days past due must not depend on a time zone.
  • remove
    OutstandingPrincipal · AmountPaid · PaidAt · DaysPastDue · IsDeleted · DeletedAt — a row is the promise; what was paid is a payout, the balance is on the register and the note.

NoteFeeConfig

dropa fee-settings table the generated code invented, with its own seeded fee values. Fee settings and their audit trail are P2P-27's, so this one goes
  • remove
    the table, its mapping, its seed rows and the service that copies from it. Until P2P-27's read service exists, the fee block on the terms stays null.

NoteReferenceSequence

keepa one-row-per-year counter that hands out the next note number: N-2026-00001, N-2026-00002 and so on. A small helper, and fine

  • replace

What must be true afterwards

Three things anyone can check

  • Every existing campaign is marked as equity, and as Islamic where it is an Islamic campaign. No campaign is left unmarked.
  • Two example notes exist for checking: a Term note still raising, which has terms and an indicative schedule but no Note row and no register rows yet, and an AR note after disbursement, which has its Note row marked Performing, its register rows Active, and a Final schedule with the Indicative one kept.
  • The database refuses a second register row for the same holder on the same note, a second current schedule for the same note, two campaigns with the same slug, and the deletion of a register row or a schedule version.
Scope guardThis ticket changes tables, columns, enums and indexes. It adds no endpoint and no business logic. How the change reaches the database, and how the example notes are created, is engineering's to decide. Increments (P2P-68), fee configuration (P2P-27), minting and close (lane E), payouts (F4.3) and servicing (lane G) are other tickets.
