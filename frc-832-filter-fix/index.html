Debugging case study · one-shot

The filter that shouted its own variable names

A staging bug where UI filters displayed raw translation keys like mysec.WithdrawalEvent instead of readable labels — traced to root cause, fixed, and verified in a single autonomous session.

FRC-832 repo PitchinCustomerWeb type Bug · i18n mode one-shot date 2026-07-14
01

What the user saw

On the PSTX Account → Transaction history screen, the new Event and Status filters rendered internal identifiers where human-readable text belonged. The menu titles showed MYSEC.EVENTFILTERS and MYSEC.STATUSFILTERS; the withdrawal option showed mysec.WithdrawalEvent. It reproduced on both desktop and mobile.

02

The investigation

Run under the systematic-debugging discipline: no fix before a verified root cause. The interesting turns weren't the bug itself — they were two traps the process caught.

  1. Phase 1 · locate

    Read the ticket, find the code

    An Explore agent tied FRC-832 to the filters built by FRC-709 on the wallet transaction-history page — the only screen pairing an Event filter with a Status filter.

  2. Phase 1 · trap #1

    The buggy code wasn't on the checked-out branch

    The agent flagged a branch discrepancy. Rather than trust it, the claim was verified empirically: the checked-out branch held the old 425-line component with no filters; the filters existed only on origin/staging (943 lines). Commit 07f97e80 was an ancestor of staging but not of HEAD. → cut the fix branch from origin/staging.

  3. Phase 1 · root cause

    Missing keys, not broken code

    The templates were already correct: option.labelKey | translate. With no MissingTranslationHandler configured, ngx-translate echoes the key verbatim when it's absent. FRC-709 added new label keys but never added the entries to en-US.json. Exactly three were missing in English.

  4. Phase 2 · trap #2

    Blast-radius check before touching shared keys

    Design wording meant editing existing labels too. A usage sweep showed BuyShares/SellShares were wallet-only (safe to repurpose), but TopUp is shared across the navbar, trading form, deposit and more — so its change was scoped as a safe title-case tweak and documented for the reviewer.

Root cause

The filter labels are ngx-translate keys. Three keys the wallet filters render — mysec.eventFilters, mysec.statusFilters, mysec.WithdrawalEvent — were never added to en-US.json, so ngx-translate displayed the key strings themselves. (zh-CN.json is a 43-key stub versus 2,505 in English — a non-functional locale, out of scope.)

03

The fix

Pure i18n data — zero code changes. The templates already pointed at the right keys; only en-US.json needed entries. Labels were set to match the ticket's design reference (kept the simple "All").

05

What made the one-shot work

  • Verify delegated findings, don't relay them

    The subagent's "wrong branch" claim was re-checked against git before acting on it. It held — but the habit is what prevents acting on a plausible-but-wrong report.

  • For bugs, branch off staging

    The reported defect lived on the integration branch, not the feature branch that happened to be checked out. Now a saved standing rule.

  • Check blast radius before editing shared strings

    One label key fed six other screens. A grep sweep turned an invisible risk into a documented, deliberate choice.

  • Confirm scope when the design says more than the arrows

    The bug's arrows pointed only at raw keys, but the reference design also renamed working labels. One clarifying question set the exact target.
